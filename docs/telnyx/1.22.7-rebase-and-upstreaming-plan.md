**Target base:** upstream `v1.22.7` (newest 1.22 patch)

## Why

1. **Pick up the multi-cert API-gateway fix for free.** Upstream `v1.22.7` already
   contains `f03f2e14a0` — the release/1.22.x backport of
   [GH-23212](https://github.com/hashicorp/consul/pull/23212) *"consolidate
   multiple file-system certificates into a single filter chain."* This is the
   exact fix `ingress-gateway-external` needs to serve two domains (dev.telnyx.tech +
   dev.clawdtalk.com) on one `:443` listener — on `v1.22.1` Envoy rejects it with
   `duplicate matcher {}` (empty-SNI filter chains).
2. **Absorb 1.22.2 → 1.22.7 security/bug patches** (CVE fixes, ACL/UI/peering
   backports) instead of carrying a stale 1.22.1 base.
3. **Reduce fork maintenance.** Several of our patches are genuine upstream bugs
   (peerstream stream lifecycle, api-gw-when-peered). Upstreaming them removes
   them from every future rebase.

## Strategy — two tracks

### Track A — Rebase the fork onto v1.22.7 (unblocks the ingress work)

Produces a deployable `1.22.7-fix` image with the multi-cert fix + our patches.

1. `git fetch upstream --tags` (have v1.22.7).
2. `git switch -c 1.22.7-fix v1.22.7`.
3. Re-apply our commits **by group**, cleaning as we go, in this order
   (**peerstream picks must follow original chronological order** — `6592b2c1`
   rewrites `stream_resources.go`/`stream_tracker.go` and the later fixes build
   on it; picking the fixes first creates avoidable conflicts):
   1. `fa04ca0a` (update peerstream resources — oldest fork commit).
   2. From `6592b2c1`: cherry-pick with `-n`, **unstage/`git rm` the `agent/uiserver/dist/**` artifacts**, keep only the `.go` peerstream changes, commit with a real message.
   3. Remaining peerstream lifecycle fixes in chronological order: `9e455b23` (#8), `967bf088`, `d447487a` (#11), `e437eff0` (#30), `55203716` (#31), `35ef647e` (#32). Expect one small conflict in `subscription_manager.go` vs upstream #23412.
   4. api-gw-when-peered: **cherry-pick upstream `34b661a9a7` (PR #23454)** instead of our `d1911`/`3534`/goldens — it's the merged version of the same fix and ships its own goldens + changelog. Skip `d1911d65`, `3534e76f`, `2def1475`, `b2bbce3f`, `f9f324f3`, `f80e9981` entirely.
   5. UI permission overrides (INFRA-14010 ×4). Trivial conflicts vs upstream lint backport #23106 in 3 ability files.
4. **Regenerate golden/xDS test fixtures** rather than porting them:
   `make golden` (or `go test ./agent/xds/... -update`) — commit the regenerated fixtures as one clean commit.
5. Build + test:
   - `go test ./agent/xds/... ./agent/proxycfg/... ./agent/consul/... ./agent/rpc/peering/... ./agent/grpc-external/services/peerstream/...`

6. Squash the housekeeping (lint/changelog/regen) so the branch is a clean stack:
   ~= peering-fixes, api-gw-peering, ui-overrides, regenerated-fixtures.
7. Tag/build the image; hand to the deploy pipeline (replaces `docker/hashicorp/consul:1.22.1`).

### Track B — Upstream the genuinely-upstreamable fixes

Goal: get the peering + api-gw-peering fixes merged into `hashicorp/consul` so
future rebases shrink. Upstream takes PRs against **`main`**; maintainers backport
to `release/1.22.x`. Base each PR on current `main`, not our fork.

**Upstream candidates (in priority order):**
1. **Peerstream stream-lifecycle race/leak fixes** — the strongest set; each is a
   small, self-contained bug with a clear failure mode:
   - stop materialized views on stream close (#32)
   - cancel peerstream subscriptions with handler context (#31)
   - keep peerstream send errors fatal (#30)
   - prevent stale stream disconnect corrupting newer stream health (`967bf088`)
   - prevent race in `HandleStream` corrupting active stream status (#8)
   - maintenance→critical in peering `flattenChecks` (#11)
   Package one bug per PR, each with a regression test + `.changelog/` entry,
   referencing the observed symptom.
2. ~~**API gateway when peered**~~ — **already upstream**: PR #23454 merged to
   `main` (`34b661a9a7`), backported to release/2.0.x. Nothing to do; the 1.22.x
   backport was explicitly declined ("no CE old-version backports"), so we carry
   the upstream commit in the fork until we move to a 2.0.x-based release.

**Not upstreamable (stay in fork):**
- INFRA-14010 UI permission overrides / sidebar fallbacks — root cause
  [#11098](https://github.com/hashicorp/consul/issues/11098) still open upstream;
  no upstream fix exists for these abilities. Keep until #11098 is resolved.
- Committed UI `dist/*` build artifacts (never upstream build output).

**Per-PR checklist:** rebase on `main`; one logical change; test that fails
without the fix; `.changelog/<pr>.txt`; `make lint`; DCO/CLA; link the internal
ticket in the PR body only if public-safe.
